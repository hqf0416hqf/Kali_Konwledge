## 一、Linux：从硬件到应用的完整路径

学习对话整理：用户想知道 `lsusb`、`lspci` 等命令在系统里究竟观察什么，而不是继续零散背命令。已有 [Linux 笔记](../WIKI/CS/tools/Linux/Linux.md) 可以承接基础目录与操作；本次重点补设备发现、驱动与内核的联系。

### 1. 先沿一条链定位问题

以 CH340 USB 转串口设备为例，简化过程如下：

```text
插入 USB 设备
  → 主机检测连接并枚举，取得描述符、设备与接口信息
  → 内核登记设备对象，为相应接口匹配驱动
  → 驱动执行 probe 等初始化过程
  → USB 串口子系统注册串口功能
  → 出现可供程序访问的设备节点，例如 /dev/ttyUSB0
  → 程序打开接口，配置串口参数并通信
```

枚举是主机发现、识别和配置设备的过程。VID/PID 是厂商与产品标识，但驱动匹配还可能使用设备或接口类别；不能理解成 Linux 看到“CH340”这个名称就猜出应该运行什么程序。

一个物理设备可以提供多个接口，例如同一 USB 设备提供视频和音频功能。不同接口可能由不同驱动管理。匹配成功后仍需初始化成功，才能形成可用的绑定关系。[Linux 官方：驱动绑定](https://docs.kernel.org/driver-api/driver-model/binding.html)

### 2. 命令分别回答什么问题

以下是 Linux 环境中的复习命令，需有相应工具包；本轮整理未运行硬件观测命令，示例没有代表本机设备清单。

- `lsusb`：列出 USB 设备及识别信息。
- `lsusb -t`：查看 USB 拓扑、接口和驱动等信息。
- `lspci -nnk`：查看 PCI/PCIe 设备、名称与数字 ID，以及相关内核驱动信息。
- `lsblk`：查看块设备及其层次；磁盘、分区、文件系统和挂载点需要分别理解。
- `lsmod`：查看当前加载的动态内核模块。
- `modinfo ch341`：查询模块信息，例如文件、依赖和匹配别名；不代表设备已经绑定成功。
- `journalctl -k`：查看可访问的内核日志，用来寻找枚举、初始化或通信错误的线索。

`lspci -k` 中的 `Kernel driver in use` 表示正在使用的驱动；`Kernel modules` 列出相关候选模块，不能只看后者就认定驱动正在工作。

可用以下顺序分析 USB 串口问题：

| 观察到的现象 | 接下来应查什么 |
| --- | --- |
| `lsusb` 看不到目标设备 | 供电、线缆、端口和枚举日志 |
| 已看到设备，但没有预期串口节点 | 接口类型、驱动匹配、初始化及串口注册 |
| 节点存在，打开时报权限不足 | 节点权限、当前用户与所属组 |
| 能打开，但数据乱码或无有效数据 | 波特率、数据格式、接线、电平和通信协议 |

这张表用于缩小排查范围，单个现象不足以确定故障原因。ST-Link 也不必然提供 `/dev/ttyUSB0`；调试接口与虚拟串口功能要按具体设备区分。

### 3. `/sys` 看关系，`/dev` 提供访问入口

`/sys` 是内核向用户空间暴露设备、驱动、总线及属性关系的接口。例如 `/sys/bus/usb/devices/` 下可以看到 USB 设备和接口对象，关联关系还可能通过符号链接表达。

`/dev/ttyUSB0` 这类设备节点供程序访问串口。其主、次设备号用于内核中的设备访问映射与实例区分，并不是 USB VID/PID。现代 Linux 通常由设备子系统、devtmpfs 和 udev 等机制共同完成节点提供、权限与链接管理；不是 `lsusb` 创建了串口文件。

也并非所有设备都以一个普通 `/dev` 节点提供功能，例如网络设备通常通过网络接口及 Socket 使用。要先看设备功能，再判断其用户接口。

### 4. 驱动是职责，模块是装载形式

**驱动**负责管理某类设备；**内核模块**是可动态装入内核的代码单元。驱动可以编译进内核，也可以作为 `.ko` 模块提供；模块还可以实现文件系统等其他功能。

因此，`lsmod` 没有某个名字，不能直接证明系统没有相应驱动。它显示的是 `/proc/modules` 中的已加载模块信息，不是硬盘上所有驱动文件的清单。[kmod：lsmod 手册](https://github.com/kmod-project/kmod/blob/master/man/lsmod.8.scd)

模块通常通过注册回调和接口参与内核工作，并不等同于一个独立用户进程。设备匹配时可能调用驱动的 `probe()`，后续 I/O 或硬件事件再触发相应代码。

常见的按需加载路径是：设备事件带来 `MODALIAS` 等匹配信息，用户空间机制据此寻找模块，模块加载后注册驱动，再尝试匹配与绑定。驱动已内建或已加载时，不需要重新走完整加载流程。

- `modprobe`：按模块名、别名与配置处理加载，并利用依赖索引自动处理模块依赖。
- `insmod`：主要按给定模块文件尝试装入，不提供同样的自动依赖解析流程。
- `depmod`：生成供模块工具使用的依赖等索引。

这里记录工具职责，本次没有加载或卸载模块。[kmod：modprobe 手册](https://github.com/kmod-project/kmod/blob/master/man/modprobe.8.scd)

## 二、USB 主机控制器、PCIe 与 SCSI 如何联系

学习对话整理：本地追问涉及“USB 主机控制器是什么”“PCI 总线有没有类似控制器”“USB 核心、SCSI 子系统是什么”。原问题中的 `pcl` 暂按 PCI/PCIe 理解，未把它解释成点云库 PCL。

### 1. 先区分硬件和内核软件

- **USB 主机控制器：** 主机侧执行 USB 通信的硬件，CPU 通过软件配置它完成传输。
- **主机控制器驱动（HCD）：** 操作该硬件的内核代码；xHCI 是常见的控制器接口规范。
- **USB 核心（usbcore）：** 提供 USB 设备管理与传输等通用接口，让外设驱动复用。
- **USB 外设驱动：** 根据设备提供的具体功能，参与输入、串口、存储等上层子系统。

可以按“外设驱动提交请求 → USB 核心提供接口 → HCD 操作控制器 → 硬件完成传输”理解职责，但这是一条简化路径，不是完整函数调用栈。[Linux 官方：USB 主机侧 API](https://docs.kernel.org/driver-api/usb/usb.html)

PCIe 中的根复合体、主机桥与根端口承担主机侧连接、配置和访问设备的相关职责；这些名称不与 USB 主机控制器一一等价。一个 PCIe USB 扩展卡可以同时是 **PCIe 设备**和 **USB 主机控制器**：

```text
CPU／内存侧 → PCIe 主机侧与链路 → USB 控制器 → USB 外设
```

这是连接方式的例子，不代表所有 USB 控制器都必须经过 PCIe；SoC 中还可能使用片上互连。根复合体、主机桥和根端口的层次参见 [Linux 官方 PCI 主机控制器文档](https://docs.kernel.org/PCI/controller/pci-controller-drivers.html)。

### 2. 为什么 U 盘也会进入 SCSI 子系统

USB 描述连接和传输的一层，SCSI 还包含存储命令体系。不同层可以组合：USB 存储设备可以通过 USB 运输 SCSI 命令，因此没有传统 SCSI 电缆，也可能在 Linux 中作为 SCSI 设备管理。

常见 USB 存储请求可简化为：

```text
应用读取文件
  → 文件系统与块层
  → SCSI 磁盘驱动与 SCSI 核心
  → usb-storage 或 uas 等 USB 存储驱动
  → USB 核心与主机控制器驱动
  → USB 控制器硬件 → U 盘
```

这解释了为什么日志可能先出现 USB 识别，再出现 SCSI 设备，最终出现 `/dev/sdX`：系统从不同层次管理同一设备。USB 键盘的功能路径则不同，不会因为通过 USB 连接就进入存储路径。[Linux 官方：SCSI 协议与总线](https://docs.kernel.org/driver-api/scsi.html#protocol-vs-bus)

## 三、数字电路与 STM32：补上“计算、保存、响应”的区别

学习对话新增了从晶体管到逻辑门、触发器和计数器的解释。本节只保留基础关系；时钟树与 TIM 周期公式沿用 [10 月 20 日记录](2026-10-20.md)，不重复抄写。

### 1. 组合逻辑计算，时序电路保存状态

MOS 晶体管可以用电压控制导电通路；其导通要结合栅源电压等条件，不能笼统说“栅极高就一定导通”。典型 CMOS 非门利用 PMOS 与 NMOS 配合实现逻辑取反。这是功能模型，不是完整器件物理说明。

组合逻辑的输出由当前输入决定，例如 AND、OR、XOR。保存数据还需要状态存储结构：典型锁存器对使能电平敏感，边沿触发器在指定时钟边沿更新状态。

对一个上升沿 D 触发器，在满足时序约束且没有复位等控制影响时，时钟有效边沿把 D 采样到 Q；边沿之间保持已存状态。多个存储位和控制逻辑可以组成寄存器，结合加一逻辑可以组成计数器。

**系统补充：** 计数器同时需要组合逻辑和状态存储。四位无符号计数器可按 `0111 → 1000` 更新，模 16 计数时 `1111 → 0000`。这说明“能加一”和“记住上次值”是两个相互配合的能力。

CPU 寄存器、外设寄存器和 SRAM 都涉及保存信息，但角色和实现不同；不能把全部存储器都视为标准 D 触发器简单堆叠。

### 2. 半加器、全加器放在什么标题下

新窗口只提出了分类问题，未获得有效技术回答。整理补充建议使用 **“组合逻辑电路 → 加法器”**，与后续“时序逻辑电路 → 触发器、寄存器、计数器”区分。这里只提供 RAW 素材，不改 [计算机组成笔记](../WIKI/CS/fundamention/Computer_Organization/Computer_Organization.md) 的目录。

半加器处理两位输入 $A,B$：

$$
S=A\oplus B,\qquad C=A\land B.
$$

$S$ 是本位和，$C$ 是向高位的进位。输入均为 1 时，输出为进位 1、本位和 0，即二进制 `10`。

全加器额外接收低位进位 $C_{in}$：

$$
S=A\oplus B\oplus C_{in},\qquad
C_{out}=(A\land B)\lor\bigl(C_{in}\land(A\oplus B)\bigr).
$$

其中 $\oplus$、$\land$、$\lor$ 分别表示异或、与、或。连接多位全加器可以实现多位加法；结果稳定需要传播时间，真实电路不是瞬时完成运算。本段全加器公式为系统补充，未做电路搭建。

### 3. 返回原程序，中断为什么仍有用

上次已经区分中断与调度；本次新增疑问是：“裸机没有任务切换，恢复原现场，中断还有什么意义？”

例如 CPU 正在计算 PID，串口收到一个字节。中断处理程序读取字节、放入缓冲区，再恢复 PID 计算。**执行位置恢复了，但接收缓冲区已经改变，有用工作已经完成。** 因而中断能响应异步事件，无须以切换任务为目的。

系统补充：保存和恢复执行现场，不是把整个内存回滚。中断处理仍会留下有意写入的数据和外设状态。实际设计还应控制处理时长，把较重的解析或计算留给合适的后续流程。

本次另外纠正了两个词义混淆：PSC 是预分频器（Prescaler），不是 C/C++ 预处理器（Preprocessor）；RCC 负责全局时钟管理，TIM 使用时钟计数，两者不是任选其一的两套定时系统。

### 2. 扫描、索引与语义检索各解决什么问题

- **直接扫描：** 查询时读取文本并匹配，结构简单，修改后下次查询直接生效。
- **倒排索引：** 预先建立“词 → 文档或位置”的映射，重复查询时可减少全量扫描，但要维护索引更新。
- **相关性排序：** 对候选结果决定先看哪些，例如 BM25；它不等于语义理解。
- **向量检索：** 用表示文本含义的向量查找相似内容，可补同义表达，但仍需检查来源和匹配质量。
- **混合检索：** 组合关键词、语义与排序机制，根据真实查询效果取舍。

对于当前小型 Markdown 仓库，先测查询延迟和结果质量，再判断是否需要更复杂的索引。SQLite FTS5 是全文检索的一个候选，支持 BM25 等能力；默认分词不能直接当成完整中文语义分词，trigram 也有短查询限制。[SQLite 官方 FTS5 文档](https://sqlite.org/fts5.html)

## 五、仿真与强化学习：环境不等于算法

## 六、概率论：把协方差与重复测量连接起来

本地新增建议是先做独立解题检验，再按错误补缺；不是重新排整门课程。已有 [概率论笔记](../WIKI/Math/Probability‑And‑Statistics/Probability.md) 和 [10 月 12 日记录](2026-10-12.md) 承接分布与标准误背景。

### 1. 协方差还需要取期望

当前笔记写了两个偏差相乘的直觉；完整的总体协方差，在二阶矩有限时为：

$$
\operatorname{Cov}(X,Y)
=E\left[(X-E[X])(Y-E[Y])\right].
$$

偏差乘积可以判断一次取值中的同向或反向偏离，期望则对这些可能结果作总体平均。协方差为零表示不相关，通常不能推出独立。

系统补充例子：若 $X$ 在 $\{-1,0,1\}$ 上等概率取值，$Y=X^2$，则 $E[X]=E[X^3]=0$，所以 $\operatorname{Cov}(X,Y)=0$；但知道 $X$ 就能确定 $Y$，两者并不独立。

### 2. 平均值为什么更稳定，又何时不成立

设固定真实距离为 $d$，第 $i$ 次观测为 $X_i=d+\varepsilon_i$，误差期望为零、方差为 $\sigma^2$，平均值为 $\bar X=\frac1n\sum_iX_i$。

系统补充：对二阶矩有限的误差，不先假设独立时，

$$
\operatorname{Var}(\bar X)
=\frac{1}{n^2}\left(\sum_{i=1}^{n}\operatorname{Var}(\varepsilon_i)
+2\sum_{i<j}\operatorname{Cov}(\varepsilon_i,\varepsilon_j)\right).
$$

独立误差的协方差为零，加上各次方差相同，才得到常用关系：

$$
E[\bar X]=d,\qquad
\operatorname{Var}(\bar X)=\frac{\sigma^2}{n},\qquad
\operatorname{SD}(\bar X)=\frac{\sigma}{\sqrt n}.
$$

严格说，不相关已足以使协方差项消失，独立是更强的充分条件。均值的标准差描述重复取样时估计量的波动，也称标准误；用样本标准差 $s$ 代替未知 $\sigma$ 得到的是估计值 $s/\sqrt n$。

若每次还存在固定偏差 $b$，则 $X_i=d+b+\varepsilon_i$，平均值的期望仍为 $d+b$。增加次数可以降低上述随机波动，却不会消除固定偏差。正相关误差也可能使平均效果差于独立模型。

这条联系直接服务于传感器融合：先明确随机变量、均值、方差和相关性，再理解滤波算法如何利用它们；不能只记“多测几次就更准”。
