
## 驱动
驱动本质上是让操作系统能够按照某种硬件接口控制具体硬件的软件；Linux 内核已经集成了非常庞大的驱动体系。

Linux 内核本身就包含了大量硬件驱动，所以很多硬件插上之后，系统直接就能用，不需要像 Windows 那样另外下载安装驱动。

```text
硬件
  ↓
Linux 内核
  ├── USB 驱动
  ├── USB-Serial 驱动
  ├── 网卡驱动
  ├── Wi-Fi 驱动
  ├── SATA/NVMe 驱动
  ├── 声卡驱动
  ├── 输入设备驱动
  └── ……
        ↓
     /dev、网络接口等
        ↓
      用户程序
```

“Linux 自带很多驱动” ≠ “Linux 自带所有硬件驱动”。

| 情况         | 典型例子                | 是否可能需要额外处理      |
| ---------- | ------------------- | --------------- |
| 内核原生支持     | USB、键盘、鼠标、NVMe、很多网卡 | 通常不用            |
| 内核支持，但需要固件 | 某些 Wi-Fi、蓝牙、显卡      | 可能需要安装 firmware |
| 厂商驱动/专有驱动  | NVIDIA GPU、部分特殊硬件   | 经常需要额外安装        |


这也是为什么 Linux 下排查硬件问题时，第一反应通常不是“去下载驱动”，而是：

lspci
lsusb
dmesg
lsmod
modprobe

先判断：

硬件有没有被发现 → 内核有没有对应驱动 → 驱动有没有加载 → 用户有没有权限 → 应用程序能不能使用。

lspci    → 看 PCI 总线上的硬件
lsusb    → 看 USB 总线上的硬件
dmesg    → 看内核发生了什么
lsmod    → 看当前加载了哪些内核模块
modprobe → 手动加载/卸载内核模块
